# Porter Finances (iPhone web app)

Personal-finance PWA for two people, reading their Tiller Google Sheet.
- Keep personal details (account names, numbers, balances, sheet ID) out of this public repo. The sheet ID is entered once per phone and kept in localStorage (`pf_sheet_id`).

- Plain HTML/CSS/JS, no build step. Files: `index.html`, `styles.css`, `app.js`, `config.js`, `sw.js`, `manifest.webmanifest`, `icons/`.
- Sign-in: after each successful redirect, `rememberAccount` stores the Google account's email (from the id_token; scope `openid email`, response_type `token id_token`; falls back to tokeninfo `sub`) in localStorage `pf_login_hint`; `startSignIn` passes it as `login_hint` so silent sign-in works even with two Google accounts on the phone. Cleared on a hard failure so the account list can show again.
- Security: the sheet stays private. The app signs in with Google OAuth (redirect flow, `spreadsheets` scope) and calls the Sheets API directly from the phone. Never publish the sheet, add a server that stores tokens, or cache sheet data in the service worker.
- Writes the app makes: (1) the Category, Note, Reviewed and Ask cells on the Transactions tab (`sheetSource.setFields`), re-checking the Transaction ID first because Tiller inserts rows; (2) deleting duplicate transaction rows (`sheetSource.deleteDuplicates`), only for groups `findDuplicates` marks safe (same ID and identical date/amount/account/description/full description, at most one category). It re-reads the sheet, backs rows up to the "Removed Duplicates" tab, re-checks IDs, deletes bottom-up, snapshots the whole ID column right before deleting, then verifies each ID still has its kept copy and that the ID column equals the snapshot minus the deleted rows. Keep these safeguards.
- `apps-script/Automation.gs` is pasted into the sheet's Apps Script by hand (Extensions > Apps Script, run `setup`). Hourly + 7 AM jobs: auto-removes exact duplicates (backup first), possible double charges, connections, fill, large/new-merchant charges, low balance, Drive backups, bills/subscriptions, budget pacing, AutoCat suggestions, reimbursements, quarterly manual-account reminder. Alerts via Pushover (keys in Script Properties) or email, logged to the "Alerts" tab. Thresholds live on the "Automation Settings" tab. Its `findDuplicates` must match the app's. Pure logic sits at the bottom of the file and is tested on the Mac with JXA (osascript).
- The app reads the "Alerts" and "Suggested Rules" tabs if they exist; approving a suggestion appends to AutoCat (appendCells) and categorizes uncategorized matches via `fixCategories`.
- The balance cross-check idea was dropped on purpose: pending charges move balances before Tiller has the transaction, which would cause false alarms.
- Sheet check only flags category names that differ from a budget category by spaces or capitals; old categories no longer on the Categories tab are ignored on purpose.
- Connections tab: bank health from Accounts tab "Last Update" (OK ≤2 days, Check 3–6, Needs a fix 7+), non-hidden accounts only; manual accounts (`manual:` IDs) are listed separately. Tiller has no public API, so refresh/fix links out to https://my.tiller.com.
- Columns are located by heading name (Tiller headings), not position.
- Preview with made-up data: open `/?demo`. macOS blocks the preview server from reading ~/Documents, so copy the folder to a scratch location and serve it from there.
- Bump `CACHE` in `sw.js` when shipping changes. The service worker fetches with `no-cache` because GitHub Pages sends max-age=600; the app reloads itself once when a new version takes over.
- Transactions tab has two custom columns added at the far right: "Note" and "Reviewed" (the app writes via `sheetSource.setFields`, which re-locates the row by Transaction ID first). The review queue = uncategorized transactions with an empty Reviewed cell.
- An "Ask" column is added by the app itself at the far right of Transactions if missing (load() appends a column and writes the header). Ask = "Yes" puts the item in the review queue; "Answered ✓" clears it. In the transaction panel, the Ask toggle and the note are only saved with "Save ✓" (or by choosing a category); Cancel and the backdrop discard them. Tax tagging was removed on purpose (the user sorts by category in Tiller at year end).
- Savings goals live on a "Goals" tab (Goal, Target, Target Date YYYY-MM, Account #, Account), created by the app on first save. Progress = the account's current balance; "on pace" compares growth since the Balance History value 90+ days ago with what's needed per month.
- Budget has a "Where it went" donut: top 5 expense categories + Other, for the month or year to date. Tapping it opens a full chart of every category (`renderChartFull`); tapping a category or slice expands its transactions under that row.
- Face ID lock is a WebAuthn passkey stored per phone (localStorage `pf_lock_cred`); asks after 5 minutes away. It is a device lock only; Google sign-in is the real protection.
- The app loads the last 13 months of transactions by default (finds the last matching row via the Date column, then fetches only rows above it); "Load months before …" / "Load transactions before …" sets `state.fullHistory` and reloads everything. Accounts are told apart by name + Account # (`acctKey`).
- Preview screenshots: headless Chrome against the scratch copy with a `preview.html` (copy of index.html plus a helper script that clicks a tab). Regenerate `preview.html` whenever index.html changes.
- The automation also removes re-imported duplicates (`findReimports`): different IDs, identical date/amount/card/description/full description, arriving 1+ day after the original for a transaction 3+ days old; never more than the number of originals; copies with notes are skipped. Setting: "Remove re-imported duplicates automatically".
- Loads and writes: every write goes through the `trackWrites` proxy around `source`. A load that overlaps a write (or starts while another load runs) is discarded and queued to run again after, so a stale read never overwrites a fresh edit. `loadData` returns 'ok' | 'queued' | 'auth' | 'sheet' | 'error'.
- `busy()` (panel, review or goal form open, or a write in flight) blocks the resume sign-in redirect and the new-version reload; a banner is shown instead. The app checks for a new version whenever it comes back to the foreground.
- Faster refresh: `findCutoffRow` remembers the 13-month boundary row in localStorage (`pf_cutoff_row`, a row number only). Between weekly full reads of the Date column it reads a window (row−500 to row+2500) and trusts it only if recent rows sit above the boundary and 200+ older rows below; otherwise it falls back to the full read.
- Connections checks (`duplicates()`, `categoryIssues()`, `connectionGroups()`) are cached per `state.data` + `writeSeq`, so tab switches don't rescan every transaction. Any local change to transactions must go through a tracked write (see `trackWrites`) or the cache goes stale.
- Quiet-account alert (`quietAccounts`, setting "Quiet account alert (days)", default 5): a card/checking/savings account with 10+ transactions in the 60 days before its newest one, whose newest transaction is 5+ days old while the account itself still updates. Catches bank feeds that refresh balances but stop sending transactions (seen with USAA R Platinum, Sept 2026, which re-sent old history instead). One alert per quiet spell.
- Split (`sheetSource.splitTransaction`), matching Tiller's own format: the original row keeps part 1 and its ID becomes `split:<ID>[1]`; a copy inserted right below gets part 2 as `split:<ID>[2]` (splitting a split row adds the next number). The new row is made with copyPaste (formulas/formatting adjust), then only ID/Amount/Category (and cleared Note/Reviewed/Ask on the copy) are set; all in one batchUpdate, then both IDs are verified. Unsaved note/Ask in the panel is saved before the split form opens; the form stays open with the error if the split fails. "Half" fills an even split. The automation never treats split rows as double charges.
- Transactions header shows the month's count of uncategorized, not-yet-reviewed transactions ("N need(s) categorizing ›", tappable: filters to Needs category for that month), or just "All categorized". The button says "Review" when the queue equals that count, otherwise "Review all (N)". The search box has a × that clears it and restores the full list.
- Dark mode: text on accent-colored buttons uses `--on-accent` (dark in dark mode) for contrast. Small buttons get a larger invisible touch area via ::after.
- Budget bar colors (`--bar-ok/-warn/-over`): light #8cc49c / #e8c56d / #e0969c, dark #79b28f / #cdb068 / #c98089. Photo-hero bars keep their own overrides.
- Manual accounts (Connections > Manual entries): each row opens a form; `sheetSource.updateManualBalance` inserts a row at the top of Balance History the way Tiller's Manual Accounts tool does (copied from the account's latest row; new Date/Time/Month/Week/Date Added as serial numbers, fresh Balance ID, Balance as a positive number), in one batchUpdate, then checks row 2's Account ID. The Accounts tab updates by its own formulas.
- Polish pass (v36): cards/heroes carry `--shadow` + `--edge`; tab bar and bottom sheets are frosted (`--glass` + backdrop blur); sheets slide up, bars grow in (scaleX), donut fades in, toast fades in/out (`.leaving`), press-down on tappable rows/buttons; all motion is disabled under prefers-reduced-motion. Money figures use `--font-num` (ui-rounded on iPhone). Section labels are 11.5px/600/0.09em. Photo heroes: 20px radius, one shared fade, inset light edge. `renderLoading` draws skeletons; `emptyHtml(icon, text, sub)` is the empty-state helper; `instDot(institution)` colors the dot before a bank name. App icon is the purple gradient in icons/icon.svg (PNGs made with qlmanage + sips); manifest background_color is the accent so the launch screen isn't white.
- Opening an account from Accounts sets `state.txFrom='home'`; Transactions then shows a "‹ Accounts" back button (clears the account filter, returns to Accounts). Tapping the Transactions tab or the account chip's × clears it.
- Recent alerts (Connections) read the Key column too: repeats of the same key show once (newest), and `alertResolved` hides `late:<merchant>:<YYYY-MM>` once that merchant has posted in that month and `quiet:<acct>:<since>` once the account has a newer transaction.
- Icons: `acctIcon(a)` picks a tile (bank/piggy/card/home/chart) from `accountKind` (group then Tiller type; manual accounts are chart unless real estate); `groupIcon(name)` matches budget group names to `GROUP_ICONS` (fallback: tag). Paths live in `ICON_PATHS` (inline SVG, no font). The title shrinks into a compact frosted bar after 28px of scroll (`.topbar.compact`); the active tab has a filled icon and pill (`::before`).
